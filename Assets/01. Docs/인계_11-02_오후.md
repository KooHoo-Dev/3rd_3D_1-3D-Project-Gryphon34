## 진행 방식 (같음)
- 설계 결정은 하나씩 나한테 물어보고 진행. 값(HP, 배율, 시간, 피해 등)은 내가 정함. 기준을 물어보면 지금 수치로 계산한 기준만. **테이블·인스펙터 값은 "수치" 단계에서 한 번에 정할 거라 지금은 묻지 말 것**
- 새 클래스·파일을 만들거나 기존 코드를 바꾸기 전에 무엇을 만들고 바꿀지 먼저 말해 줘
- 코드만 짜 줘. 에디터 작업(애니메이터·클립·씬·프리팹)은 내가 함. 대신 할 일을 구체적으로 (칸 이름, Tag, 트리거, 화살표 조건, Has Exit Time, 어느 오브젝트에 무엇을). UI처럼 만들기 번거로운 건 `00. Study/20. BossRaid/Editor`의 빌더 메뉴(예: `HunterBookBuilder`, `VillageMenuBuilder`)처럼 **에디터 메뉴 한 번으로 만들어지게** 해도 됨
- 애니메이터·프리팹 확인은 파일을 통째로 읽지 말고 스크립트로 칸·화살표·값만 뽑기. **Python 없음** → `perl`(Git Bash)이나 grep. YAML을 `\n--- !u!` 단위로 나눠서. `PlayerGreatSword.controller`는 CRLF라 `tr -d '\r'`부터
- 컴파일 확인: 프로젝트 루트에서 `Assembly-CSharp.csproj`를 `TmpCheck.csproj`로 복사해 `dotnet build TmpCheck.csproj -nologo -v q` → 끝나면 지우기
  - 새 .cs가 Unity에서 아직 csproj에 안 들어갔으면 perl로 `<Compile Include="Assets\...\새파일.cs" />` 줄을 임시 csproj에 넣기 (sed는 `\` 때문에 깨짐 → perl 스크립트 파일에 `index($_, '기준 줄')`로)
  - 에디터 스크립트는 `Assembly-CSharp-Editor.csproj`를 복사하고, 그 안의 `ProjectReference Include="Assembly-CSharp.csproj"`를 임시 런타임 csproj로 바꿔서 빌드
- 문서(.md·.tsv)는 **CRLF**. 고친 뒤 줄 끝이 섞이지 않았는지 확인
- 끝나면 작업기록 18번에 이어서(18-11~), GDD는 해당 절 "변경 (11/02 정리)" 표에 줄 추가 (예전 결정은 덮어쓰지 말고 전/후)

### 요리·장비 효과 정리
| 문제 | 결정 |
|---|---|
| 꼬리 고기 스튜 "태클 중 받는 피해 −20%" (태클을 빼서 효과 없음) | 퍼펙트 가드 피로 +N / **퍼펙트 가드 때 보스 피로 +N** ✅ / 태클 효과만 빼기 → `RecipeTable.tsv`에 `PerfectGuardFatigue` 열 (지금 전부 0), `TackleReduce` 0.2 → 0 |
| 가드 스태미나 감소가 더해져서 철 대검 0.6 + 비늘 세트 0.3 + 심장 찜 0.3 = 1.2 → **가드가 공짜** | **곱하기** ✅ / 더하기 + 상한 / 값만 낮춤 → (1 − 방어구)(1 − 요리)(1 − 철 대검). 셋 다 −80% |
| 용뿔 `BrokenPartBonus` 1 → 용뿔 = 꼬리뼈 | 수치 단계에서 (기준: 깨진 부위를 때리는 비율이 (r ÷ 1.47 − 1) ÷ (b − 1)보다 높으면 용뿔이 셈) |
| 대장간 "가드 +0.6" 문구 | "가드 스태미나 −60%" |
