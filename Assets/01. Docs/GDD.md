# 보스 레이드 게임 기획서 (통합본)

---

## 1. 게임 개요

**한 줄 소개:** 망자가 된 사냥꾼이 마을의 화톳불에서 준비하고, 거대한 화룡을 사냥하고, 그 소재로 강해져 다시 도전하는 1인 보스 레이드 액션.

| 항목 | 내용 |
|---|---|
| 장르 | 3D 3인칭 보스 레이드 액션 |
| 플레이 | 1인, PC (키보드 · 마우스) |
| 엔진 | Unity, 3인칭 락온 카메라 |
| 구성 | 마을과 보스 투기장. 보스 하나를 단계별로 사냥 |
| 아트·애니메이션 | 보유 에셋 사용 (직접 제작 없음) |
| 개발 기간 | 10/21 ~ 11/04 (1인, 주말 포함) |
| 발표 | 11/04 |
| 목표 플레이 시간 | 30~40분 |
| 레퍼런스 | 몬스터헌터, 다크소울 |

시스템은 몬스터헌터에서(실력 + 준비, 부위파괴, 보스 소재로 장비 제작), 다크소울에서(소울 드랍, 인간성) 가져옵니다. 몬헌의 친목(4인 협동)이 빠진 자리를 다크소울의 **잃을 것을 들고 싸우는 긴장**이 채웁니다.

| | 몬스터헌터 | 다크소울 | 우리 게임 |
|---|---|---|---|
| 핵심 미학 | 도전, 친목, 판타지 | 도전, 판타지 | 도전, 감각 |
| 이기는 방법 | 실력 + 준비 | 실력 | 실력 + 준비 |
| 긴장의 원천 | 3번 죽으면 실패 | 소울을 잃을 수 있음 | 소울과 사람 상태를 잃을 수 있음 |
| 성장 | 소재 → 장비 | 레벨업 | 소재 → 장비, 인간성 → 회복약 |

### 디자인 원칙

1. **레벨은 없다.** 성장은 장비, 인간성, 식사로만 한다. 실력을 수치로 밀어붙이지 못하게.
2. **모든 죽음은 다음 판의 준비가 된다.** 준 피해와 얻은 소재는 죽어도 남는다.
3. **억까가 있어도 버틸 수 있게.** 대부분의 공격은 예비동작을 보고 구르기, 가드, 태클, 상쇄 중 잘 맞는 대응을 고를 수 있지만, 모든 공격에 깔끔한 답을 두지는 않는다. 피하기 어려운 공격은 회복약, 인간성, 방어구로 버틸 수 있게 하고, **직격 한 방**에 죽는 공격은 두지 않는다. 단, 대응법(구르기)이 있는 화염 상태는 방치하면 죽을 수 있다.
4. **새 시스템은 하나씩 연다.** 첫 판은 공격, 구르기, 회복약만으로 싸울 수 있다.
5. **코어 루프부터.** 매 개발 단계가 끝날 때마다 처음부터 끝까지 플레이할 수 있어야 한다.

## 2. 플레이어 경험 목표

> **"지난 판에 나를 죽인 보스의 공격을, 다음 판엔 준비한 장비와 익힌 손으로 받아친다."**

죽음 → 준비 + 연습 → 받아침.

- **지난 판에 나를 죽인** → 잃을 것을 들고 싸우는 긴장
- **준비한 장비** → 준비가 곧 플레이
- **익힌 손** → 보스를 읽는 사냥
- **받아친다** → 강해짐의 확인 (위협이 기회로 바뀜)

### 한 판의 경험

1. **화톳불, 고민:** 무엇을 먹을지, 인간성을 쓸지, 소울을 쓰고 갈지 들고 갈지
2. **안개문, 긴장:** 모아둔 소울을 들고 투기장에 들어간다
3. **교전 초반, 압박:** 보스의 공격을 피하기 바쁘다
4. **전환:** 물기를 상쇄로 받아치자 보스가 휘청이고, 결국 지쳐서 브레스가 불발된다
5. **해방:** 그 틈에 풀차지를 모아 내려치고, 꼬리가 잘려나간다
6. **귀환, 다음 목표:** 얻은 소재로 무엇을 만들지 생각한다

## 3. 코어 루프

**화톳불에서 준비 → 보스 사냥 → 보상 → 대장간에서 제작 → 다시 준비.** 한 바퀴는 약 5~7분(준비 1분, 전투 3~5분, 제작 1분)이라 죽어도 바로 다시 들어갈 수 있습니다.

```
 [화톳불: 준비] ──▶ [안개문] ──▶ [투기장: 사냥] ──┬─ 처치 ──▶ 보상(소울·소재·인간성) ─┐
       ▲                                         └─ 사망 ──▶ 준 피해만큼 소울 + 얻은 소재 ┤
       │                                              (들고 간 소울은 투기장에 드랍)    │
       └──────────────── [대장간: 제작·강화] ◀─────────────────────────────────────┘
```

죽어도 준 피해만큼의 소울과 얻은 소재는 남기 때문에, 실패한 판도 다음 판의 준비가 됩니다. 잃는 것은 들고 온 소울과 사람 상태뿐이고, 둘 다 다음 판에 투기장에서 회수할 수 있습니다.

### 세 겹의 루프

| 루프 | 내용 |
|---|---|
| 전투 루프 (초 단위) | 예비동작을 읽는다 → 공격에 맞는 대응을 고른다 → 틈에 치거나 차지를 모은다 → 스태미나를 보고 거리를 잰다 |
| 사냥 루프 (분 단위) | 화톳불에서 준비 → 사냥 → 보상 또는 사망 → 대장간에서 제작 |
| 진행 루프 (게임 전체) | 1단계 첫 처치 → 뿔·꼬리를 노리는 재사냥으로 무기 갈래와 화룡 세트 → 2단계 해금 → 화염에 막힘 → 방어구·요리·호석으로 대비해 돌파 |

## 4. 전투

무기는 대검 하나입니다. 회피 수단이 하나면 모든 공격의 답이 같아지므로, 대응 수단의 역할을 나눠 **공격마다 잘 맞는 대응이 다르게** 합니다. 다만 모든 공격에 깔끔한 답이 있지는 않습니다. 피하기 어려운 공격은 회복약, 인간성, 방어구로 버티는 것까지가 공략입니다.

- **구르기:** 큰 공격, 가드할 수 없는 공격을 피한다
- **가드:** 안전하지만 스태미나가 깎이고 밀려난다
- **태클:** 가벼운 공격을 버티면서 차지를 이어간다
- **상쇄:** 특정 공격을 정면으로 받아친다. 위험하지만 보스를 크게 지치게 한다

### 플레이어 기본값

- HP 100, 스태미나 100 (행동을 멈추고 2초 뒤 초당 35 회복)
- **지침:** 무엇으로든(달리기·구르기·공격) 스태미나가 0이 되면, 하던 행동을 끝낸 뒤 주저앉아 무방비. 주저앉은 동안에도 회복 대기 시간이 흘러서 회복이 시작되면(2초) 일어남. 일어난 뒤에는 Shift를 뗐다가 다시 눌러야 달릴 수 있음 (결정 10/27)
- 회복약 3개로 시작, 1개당 HP 50, 마시는 1.2초 동안 무방비. 마을에 돌아오면 자동 보충
- 레벨 없음. 수치는 장비, 인간성, 식사, 호석으로만 바뀜

### 행동 전환

대기 상태에서는 태클을 뺀 모든 행동을 바로 쓸 수 있습니다. 행동 중에는 아래 표에 있는 행동으로만 넘어갈 수 있고, 나머지는 그 행동이 끝나 대기로 돌아온 뒤에 가능합니다.

| 현재 행동 | 넘어갈 수 있는 행동 | 비고 |
|---|---|---|
| 대기 | 좌클릭, 가드, 구르기, 상쇄 | 태클 불가 |
| 차지 콤보 — Windup | 태클 | |
| 차지 콤보 — Hold | 태클, 구르기 | |
| 차지 콤보 — Release | 다음 타 (입력 창 안에서만) | 구르기·태클 불가 |
| 가드 중 | 좌클릭, 구르기 | 누르는 즉시 전환 |
| 태클 후 | 좌클릭, 구르기, 가드 | |
| 상쇄 후 | 좌클릭, 구르기 | |
| 구르기 | 없음 | 후딜까지 끝나야 다음 행동 |

- 피격은 위 표와 관계없이 모든 행동을 끊습니다.
- 차지 중 우클릭은 태클입니다. 상쇄는 공격 중이 아닐 때 두 버튼을 0.1초 안에 함께 눌러야 나갑니다. 좌클릭을 살짝 먼저 눌러 Windup이 시작됐더라도 0.1초 안에 우클릭이 들어오면 상쇄로 바꿉니다.

| 3 | 1.5초 | ×1.8 | |

- 차지 시간은 **누른 순간부터** 잽니다 (Windup 시간 포함).
- 단계는 **버튼을 뗀 순간** 확정합니다. Windup 중에 떼도 Windup은 끝까지 재생한 뒤 내려치지만, 단계는 뗀 순간의 값(0단계)입니다.
- 단계가 오를 때마다 빛·소리 연출
- 태클은 단계를 올리지 않음. 태클 중에도 차지 타이머는 계속 흐름
- 3단계 위로는 오르지 않음 (과충전은 미결정 사항 참고)

### 타별 차이

단계 배율은 모든 타가 공유하고, 타마다 기본 계수를 곱합니다. 뒤로 갈수록 강하지만 길고 무겁습니다.

| 타 | 기본 계수 | 비고 |
|---|---|---|
| 1타 | ×1.0 | 내려베기 |
| 2타 | ×1.2 | |
| 3타 | ×1.5 | 콤보 마무리. 끝나면 콤보 초기화 |

- 최종 피해 = 무기 공격력 × 타 계수 × 단계 배율 (수치는 초기값, 테스트하며 조정)
- 이전 타의 Release 후반(입력 창)에 다시 누르면 다음 타의 Windup으로 이어집니다. 창이 닫히면 1타로 초기화합니다.

### 공격 종류별 대응

보스 패턴마다 아래 태그 중 하나를 붙입니다. 표의 **최선**은 가장 잘 맞는 대응이고, 그 외의 "가능"으로도 버틸 수는 있습니다.

| 태그 | 예시 | 구르기 | 가드 | 태클 | 상쇄 |
|---|---|---|---|---|---|
| 가벼운 공격 | 앞발 할퀴기 | 가능 | 가능 | **최선** (차지 유지) | 가능 (보스 피로 상태) |
| 상쇄 가능 | 물기 | 가능 | 가능 | 불가 | **최선** (보스 피로 상태) |
| 가드 불가 | 앞발 내려찍기, 착지 | **최선** | 붕괴 | 불가 | 불가 |
| 화염 | 브레스 | **최선** (옆으로 빠지기) | 가능 (스태미나 크게 소모) | 불가 | 불가 |

- 불가인 대응을 쓰면 일반 피격으로 처리합니다.
- 상쇄는 **물기와 앞발 할퀴기에만** 통합니다 (결정 10/26). 나머지 공격에 상쇄를 쓰면 일반 피격입니다. 상쇄할 공격이 분명해야 배우는 맛이 살아납니다.
- 가드와 태클은 입력 + 애니메이션 + **받는 피해 감소**가 핵심입니다. 가드는 가드 불가 공격에 붕괴, 태클은 차지 중에만 씁니다.
- 화염 공격에 맞으면 피해와 함께 **화염 상태**가 됩니다 (아래 "화염 상태").

### 억까 패턴과 버틸 수단

- 피하기 어려운 공격(넓은 화염 장판, 연속 공격 등)도 일부 둡니다. 모든 공격을 완벽히 피하게 만들려고 패턴을 깎지 않습니다.
- 대신 **한 방에 죽지 않게** 합니다. 공격 한 번의 **직격** 피해는 맨몸 최대 HP의 60%를 넘지 않게 잡습니다 (초기값). 2단계 공격력 ×1.3을 곱해도 넘지 않게 합니다.
- 화염 상태의 지속 피해는 예외입니다. 구르기로 끌 수 있으므로 방치하면 죽을 수 있습니다. 대신 브레스 **직격**은 60% 이하로 잡아서, 맞은 뒤 굴러서 끌 틈을 남깁니다.
- 맞았을 때 회복할 틈을 줍니다. 큰 공격 뒤에는 회복약을 마실 수 있는 틈을 둡니다.
- 버틸 수단은 회복약(인간성을 태워 늘림), 인간성 사용(전투 중 전회복), 방어구(피해 감소)입니다. 억까 패턴이 이 시스템들을 쓸 이유가 됩니다.

### 화염 상태 (결정 10/26)

몬스터헌터의 화염 상태이상과 같은 방식입니다.

- 브레스 등 화염 공격에 맞으면 **직격 피해 + 화염 상태**
- 화염 상태 동안 HP가 **계속 주르륵 닳음** (틱 단위로 뚝뚝 깎지 않음). 초당 피해 × 시간
- **구르기 3번**이면 꺼짐. 안 굴러도 일정 시간이 지나면 꺼짐 (시간은 테스트하며 조정)
- 지속 피해는 **피격이 아님**: 행동을 끊지 않고, 가드·태클·상쇄 판정도 거치지 않음. HP만 깎고 0이 되면 사망
- 불 저항(화룡 비늘 세트, 화룡 심장 찜, 화염 저항의 호석)은 직격과 지속 피해에 **모두** 적용
- 화염 상태로 죽을 수 있음 (디자인 원칙 3 참고)

### AI 규칙

- 상태머신(Behavior Designer): 대기 → 거리 판단 → 패턴 선택 → 예비동작 → 실행 → 틈 → 대기
- **같은 시작동작에서 분기:** 고개를 뒤로 젖히면 물기, 거기서 더 높이 들면 브레스. 앞발을 당기면 할퀴기, 높이 들면 내려찍기
- **플레이어를 읽는 가중치:** 옆·뒤에 2초 이상 붙으면 몸을 돌리며 할퀴기 확률 증가, 멀리 있으면 브레스(2단계는 돌진) 증가, 회복약·인간성을 쓰면 브레스
- 같은 패턴 2연속 금지
- 패턴 하나 = 애니메이션 + 히트박스 활성 구간 + 태그 + 틈 + 스태미나 소모를 담은 데이터(ScriptableObject). 2단계는 이 데이터 묶음을 바꿔 끼우는 것으로 만듭니다.

## 6. 자원과 죽음의 규칙

자원은 소울, 소재, 인간성 세 가지입니다. 죽었을 때 **잃는 것은 "들고 있던 소울"과 "사람 상태"뿐**이고, 그 판에 해낸 것(준 피해, 부위파괴)은 남습니다.

| 자원 | 얻는 곳 | 쓰는 곳 | 죽으면 |
|---|---|---|---|
| 소울 | 보스 처치, 준 피해 | 무기·방어구 강화, 호석, 요리 재료 | 들고 있던 양이 투기장에 떨어짐 |
| 소재 | 처치 보상, 부위파괴, 체력 구간 달성 | 무기, 방어구, 호석, 요리 | 절대 안 잃음 (인벤토리) |
| 인간성 | 단계별 첫 처치, 부위파괴 10% | 사용(사람 상태) 또는 태우기(회복약 +1) | 가진 것은 안 잃음. 사람 상태만 잃음 |

### 소재와 역할

보스가 하나라 소재 종류가 적습니다. 한 소재를 모든 시스템이 달라고 하면 고민이 아니라 정체가 되므로, **주 용도 하나 + 경쟁 용도 하나**만 둡니다.

| 소재 | 출처 | 주 용도 | 경쟁 용도 |
|---|---|---|---|
| 화룡 비늘 | 1단계 처치 3~4개, 체력 25/50/75% 달성 시 1개씩 | 방어구 | 무기 갈래 |
| 뿔 | 뿔 파괴 | 용뿔 대검 | 파괴의 호석 |
| 꼬리 가시 | 꼬리 절단 | 꼬리뼈 대검 | — |
| 꼬리 고기 | 꼬리 절단 | 요리 | — |
| 분노 비늘 | 2단계 처치 3~4개 | 무기 +1 강화 | 맞부딪침의 호석 |
| 화룡 심장 | 2단계 처치 20% | 요리(심장 찜) | — |

### 죽었을 때

1. 이번 판에 **준 피해 비율만큼 소울**을 받음 (처치 보상의 최대 60%)
2. 이번 판에 부위파괴·체력 구간으로 얻은 **소재도 받음**
3. **원래 들고 있던 소울은 죽은 자리에 떨어짐**
4. 사람 상태와 식사 효과가 사라지고 망자로 돌아감 (화면이 창백해짐)
5. 다음 판 투기장에서 떨어진 소울을 주우면 소울 + 마지막 사람 상태와 식사가 돌아옴
6. 회수 못 하고 또 죽으면 떨어진 소울의 **절반은 화톳불로** 돌아오고 나머지는 사라짐

| 못 주운 채 처치하면 (D4) | 미정 | **그대로 남음**, 다음 판에 주우러 감 | 10/31 |
| 위치 저장 | — | `Progress.droppedSoul` (`amount`, `x, y, z`, `wasHuman`). 투기장 시작 때 `HuntManager`가 생성, `PickupSouls`가 줍기 | 10/31 |

소울을 잃는 사람은 **모아둔 사람뿐**입니다. 매번 다 쓰고 들어가면 잃을 게 없고, 비싼 장비나 호석을 사려면 모아야 합니다. 그래서 용뿔 대검·방어구·호석 가격은 **두세 판은 모아야 살 수 있게** 잡습니다.

## 7. 성장

레벨은 없습니다. 가장 큰 성장은 플레이어의 손이고, 게임 안의 성장은 그 손을 돕는 세 갈래뿐입니다. 장비는 피격 한두 번의 여유를 줄 뿐, 패턴을 모르고도 이기게 만들지 않습니다.

| 성장 | 무엇으로 | 지속 | 플레이어의 선택 |
|---|---|---|---|
| 실력 | 패턴을 익히는 것 | 영구 (플레이어) | 어떤 공격에 무엇으로 대응할지 |
| 장비 | 보스 소재·부위파괴 소재 + 소울 | 영구 | 받아치는 무기와 몰아치는 무기 중 어느 갈래로 갈지, 그러려면 어느 부위를 노릴지 |
| 인간성 | 보스 첫 처치, 부위파괴 | 쓰면 한 판, 태우면 영구 | 지금 사람이 되어 강해질지, 화톳불에 태워 회복약을 영원히 늘릴지 |
| 준비 | 요리, 호석 | 한 판 | 이번 사냥을 어떤 방식으로 풀지 |

### 성장의 리듬: 문제가 먼저, 장비가 답

| 단계 | 역할 | 플레이어가 느끼는 문제와 답 |
|---|---|---|
| 1단계 | 패턴을 배우는 벽 | "이 공격을 어떻게 피하지?" → 실력과 첫 장비 |
| 2단계 | 준비를 요구하는 벽 | "불 때문에 버틸 수가 없네" → 화염에 강한 방어구, 요리, 호석 |
| 3단계 (확장) | 모든 것을 시험하는 벽 | 비행과 2페이즈, 날개 부위파괴 |

#### 변경 (10/30 정리)

| 2단계 | 불 → 방어구, 요리, 호석 | 그대로 + 완전히 높은 벽. 요리를 여기서 배우고 장비 강화·인간성을 적극적으로 | 10/30 |
| 3단계 (확장) | 비행과 2페이즈 | 공중은 2단계로 당겨 옴 (2단계 표 참고) | 10/30 |

### 요리

생존(HP)은 인간성과 방어구가 맡으므로, 요리와 호석에는 HP 효과를 넣지 않습니다.

- 화톳불 옆 **냄비 하나**. NPC 없음. 기본 재료도 냄비에서 소울로 삼
- 출격 전 **한 끼만**. 효과는 사냥 한 번 동안
- 이기고 돌아오면 끝. 죽으면 사라지고, 떨어진 소울을 회수하면 돌아옴
- 식사 스킬은 **레시피마다 고정** (랜덤 아님)

## 8. 계속 플레이하게 만드는 장치

"한 판만 더"를 만드는 것은 세 가지입니다. 져도 남는 것, 되찾아야 할 것, 다음에 노릴 것.

| 장치 | 어떻게 | 플레이어의 생각 |
|---|---|---|
| 져도 남는다 | 준 피해만큼의 소울과 얻은 소재는 죽어도 받는다 | "이번 판도 헛수고는 아니었어" |
| 되찾으러 간다 | 들고 있던 소울과 사람 상태는 투기장에 떨어진다. 두 번 연속 죽어도 절반은 돌아와서 막히지는 않는다 | "내 소울 주우러 바로 다시 간다" |
| 다음 목표가 보인다 | 원하는 무기 → 필요한 부위 → 이번 사냥에서 노릴 곳이 정해진다 | "이번엔 꼬리를 자른다" |
| 같은 보스, 다른 싸움 | 노리는 부위, 무기 갈래, 요리와 호석 조합이 매번 다르다 | "이번엔 받아치는 걸로 해볼까" |
| 강해진 게 보인다 | 예전에 도망치던 공격을 받아치고, 새 장비로 예전 보스를 빠르게 잡는다 | "내가 진짜 늘었네" |
| 다음 벽이 열린다 | 첫 처치로 다음 단계 보스가 해금된다 | "저건 또 어떻게 잡지?" |
| 한 판이 짧다 | 몇 분짜리 사냥이라 다시 들어가는 부담이 적다 | "딱 한 판만 더" |

## 10. 구현 메모 (Unity)

### 전체 구조

- **버프 목록 하나로 계산:** 최대 HP, 스태미나, 차지 속도, 불 저항 등은 처음부터 **버프들의 합**으로 계산. 장비·인간성·요리·호석이 모두 "버프 하나 추가"로 끝나야 요리·호석을 나중에 붙이기 쉬움
- **보스 패턴 = ScriptableObject:** 애니메이션 + 히트박스 활성 구간 + 태그 + 예비동작 길이 + 틈 + 스태미나 소모. 단계별로 패턴 묶음을 바꿔 끼움
- **보스 단계도 데이터로:** HP, 공격력 배율, 색, 패턴 묶음을 단계 데이터 하나에 담음. 1단계를 이렇게 만들어 두면 2단계는 데이터 하나 추가로 끝남. Boss.cs에 1단계 수치를 박지 않기
- **플레이어 피격은 한 곳에서:** `PlayerHealth.TakeDamage`에서 "지금 플레이어 상태(가드·태클·상쇄 판정 중) × 보스 공격 태그(상쇄 가능·가드 불가·화염)"로 결과를 정함. 그래서 보스 공격 정보(`AttackInfo`)에 태그가 필요
- **보스 피격 구조:** 콜라이더마다 `Hurtbox`(IDamageable) → 소속 `BossPart`(부위 하나, 내구도) → `Boss`(HP·피로). 레이어 `BossHurtbox`만 칼에 맞음. 콜라이더를 추가하면 메뉴 BossRaid > Setup Dragon Hurtboxes 실행
- **공격 태그 판정:** 플레이어 대응(구르기/가드/태클/상쇄)과 보스 공격 태그 조합으로 결과를 결정하는 함수 하나 (4장 대응 표 그대로)

### 차지 콤보 (3타)

한 타의 흐름은 모두 같고, 타마다 다른 건 데이터뿐입니다. 로직 하나를 3번 재사용합니다.

```
[Move] --누름--> [Windup] --누르고 있음--> [Hold 반복] --뗌--> [Release]
                    └--Windup 중에 뗌: Windup 끝까지 재생 후--┘
[Release] --입력 창 안에서 누름--> 다음 타의 [Windup]
[Release] --창 닫힘 / 클립 끝--> [Move], 콤보 1타로 초기화
```

- **클립 자르기:** 내려치는 클립을 타마다 임포트 설정에서 **Windup / Hold / Release** 세 개로 자름 (3타 × 3 = 9개, 우선 1타만)
  - Windup → Hold: Exit Time 자동 전환
  - Hold: Loop 켬 (2~5프레임, 살짝 떨리는 느낌)
  - Release: 코드에서 `CrossFade`로 넘김
- **차지 단계는 애니메이션이 아니라 코드 타이머.** 단계별 시간·배율은 `StreamingAssets/ChargeTable/ChargeTable.tsv`(Level, Time, Damage, Fatigue)에서 읽음 (`ChargeTable.Get(time)`)
- 최종 피해 = `GreatSword.attackPower`(무기 공격력, 강화·무기 교체로 바뀜) × `WeaponCollider.motionValue`(타 계수) × 차지 배율
  - 타이머는 누른 순간 시작, 단계는 **떼는 순간 확정**해서 저장
  - Windup 중에 떼면 `releaseQueued` 플래그만 세우고, Windup이 끝나는 시점에 Release로 넘김
- **입력:** `GetMouseButtonDown`(Windup 시작 / 다음 타 예약), `GetMouseButton`(차지 유지), `GetMouseButtonUp`(단계 확정)
- **콤보 입력 창:** Release 클립 뒷부분에 애니메이션 이벤트 `ComboOpen` / `ComboClose`. 창이 열린 동안 누르면 다음 타 예약
- **타별 데이터는 배열로:** `[Serializable] class ComboStep { Windup/Hold/Release 상태 이름, 타 계수, 스태미나 }`를 배열로 두고 인스펙터에서 조절. 코드에 `if (combo == 1)` 분기를 만들지 않음
- Animator 전환 화살표보다 **코드에서 CrossFade로 직접 넘기는 방식**
- `Animator.speed = 0`으로 멈추는 방식은 쓰지 않음 (전체 레이어가 멈추고 타이밍 버그)
- 구간별 속도(준비 느리게/내려치기 빠르게/후딜 느리게)는 State의 Speed로

### 태클

- 차지 중(Windup·Hold) 우클릭 → `Tackle` CrossFade, 끝나면 그 타의 Hold로 복귀
- 차지 한 번에 한 번만 (`tackleUsed`), 스태미나 소모
- 단계 보너스 없음. 차지 타이머는 태클 중에도 계속 흐름
- 태클 중 손을 떼면 입력을 기억했다가 태클 끝 프레임에 Release로 연결 (추천, 미확정)
