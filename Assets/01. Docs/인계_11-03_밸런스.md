## 나와 일하는 방식 (중요 — 꼭 지키기)
- **항상 한국어로.**
- 학습 프로젝트라 **코드는 기본적으로 내가 짬.** 내가 "너가 해 / 구현해 줘 / 반영해 줘"라고 한 **그 조각만** 하기 (다음 조각까지 넘어가지 말 것)
- 맡겨도 **새 클래스·파일을 만들거나 기존 코드를 바꾸기 전에** 무엇을 만들고 무엇을 바꿀지 먼저 말하고 승인받기
- **값(수치)은 절대 마음대로 정하지 말기.** 지금 값 + **선택지 2개(짧은 표) + 각각의 느낌**을 보여 주고 내가 고름. 한 번에 한 항목씩
- "왜 ~해?"라고 물으면 **이유를 바로** 답하기 (되묻지 말 것)
- 설명은 짧고 단계별로. 큰 설명을 한꺼번에 주면 힘듦
- **에디터 작업은 기본적으로 내가 함** → 어느 프리팹·오브젝트·컴포넌트·칸·값인지 **정확하게.** 내가 "에디터에서 반영해 줘"라고 하면 프리팹 YAML을 직접 고쳐도 됨 (고친 뒤 값을 다시 읽어서 확인)
- 코드 리뷰는 전체 코드를 다시 쓰지 말고 **줄 위치를 짚어서** 설명
- **작업기록**: 한 덩어리 끝날 때마다 `작업기록.md`에 이어 쓰기 (지금은 21번까지). 형식은 기존과 같게 — 고른 것/선택지/결정 표, 파일/바뀐 것 표, 에디터 작업 체크박스, 테스트. **누가 했는지 표시 금지** (이모지·"누가" 칸·AI 언급 X)
- **GDD**: 예전 결정은 덮어쓰지 말고 섹션 아래에 `#### 변경 (날짜 정리)` 표(항목 / 전 / 후 / 언제)를 추가
- 이름 규칙: 이벤트 = `On`+일어난 일, 핸들러 = `Handle`+무엇
- 커밋은 내가 직접. **`53f80ccb` 이후 것은 아직 커밋 안 됨**

## 작업 요령 (도구)
- 프리팹·씬 YAML은 통째로 읽지 말고 grep/perl로 필요한 것만 (**Python 없음**, perl은 있음). 값 확인은 스크립트 GUID로 MonoBehaviour를 찾아 칸만 뽑기
- 씬이 프리팹 값을 덮어쓰는지 확인: 씬 파일에서 `propertyPath: <칸 이름>` grep (이번 값들은 두 씬 다 덮어쓰기 없음)
- 컴파일 확인: 프로젝트 루트에서 `Assembly-CSharp.csproj` → `TmpCheck.csproj` 복사 → (새 .cs가 csproj에 없으면 `<Compile Include="Assets/…/새파일.cs" />` 줄 추가, **슬래시는 /**) → `dotnet build TmpCheck.csproj -nologo -v q` → `TmpCheck.csproj` 지우기. 경고 8개는 원래 있던 것
- 문서(.md·.tsv)는 CRLF. .cs는 그 파일의 기존 줄바꿈 그대로 (`Flow/`는 CRLF)

| 가드 | 피해 −80%, **막은 피해 1당 스태미나 1.5** (화염 ×1.5), 퍼펙트 가드 피로 10 | `PlayerController` |
