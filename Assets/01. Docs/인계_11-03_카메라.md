## 나와 일하는 방식 (중요, 꼭 지키기)
- **항상 한국어로.**
- 학습 프로젝트라 **코드는 기본적으로 내가 짬.** 내가 "너가 해 / 구현해 줘 / 반영해 줘"라고 한 **그 조각만** 하기
- 맡겨도 **새 클래스·파일을 만들거나 기존 코드를 바꾸기 전에** 무엇을 만들고 무엇을 바꿀지 먼저 말하고 승인받기
- **값(수치)은 절대 마음대로 정하지 말기.** 지금 값 + **선택지 2개(짧은 표) + 각각의 느낌**을 보여 주고 내가 고름. 한 번에 한 항목씩
- "왜 ~해?"라고 물으면 **이유를 바로** 답하기 (되묻지 말 것)
- 설명은 짧고 단계별로. 큰 설명을 한꺼번에 주면 힘듦
- **에디터 작업은 기본적으로 내가 함** → 어느 에셋·오브젝트·컴포넌트·칸·값인지 **정확하게.** 내가 "에디터에서 반영해 줘"라고 하면 YAML을 직접 고쳐도 됨 (고친 뒤 값을 다시 읽어서 확인)
- 내가 "했어"라고 하면 파일에서 값을 다시 읽어 확인. ⚠ Unity가 아직 저장 안 했으면 옛 값이 보임 → 다르면 "저장(Ctrl+S / File → Save Project) 했는지"부터 물어보기
- 코드 리뷰는 전체 코드를 다시 쓰지 말고 **줄 위치를 짚어서** 설명
- **작업기록**: 한 덩어리 끝날 때마다 `작업기록.md`에 이어 쓰기 (다음은 26번). 형식은 기존과 같게 (고른 것/선택지/결정 표, 파일/바뀐 것 표, 에디터 작업 체크박스, 테스트). **누가 했는지 표시 금지**
- **GDD**: 예전 결정은 덮어쓰지 말고 섹션 아래에 `#### 변경 (날짜 정리)` 표(항목 / 전 / 후 / 언제)를 추가
- 이름 규칙: 이벤트 = `On`+일어난 일, 핸들러 = `Handle`+무엇
- 주변 코드 스타일에 맞추기 (한글 주석, 짧은 줄 주석)
- 내가 UI·셰이더 "갤러리 표본" 프롬프트를 붙여 넣을 때가 있음 → 통째로 옮기지 말고 **우리 코드와 비교해서 쓸 것만** 표로 골라 주기 (namespace·전체 출력 같은 표본 규칙은 따르지 않음)
- 커밋은 내가 직접. **`53f80ccb` 이후 것은 아직 커밋 안 됨**

## 작업 요령 (도구)
- 프리팹·씬 YAML은 통째로 읽지 말고 grep/perl로 필요한 것만 (**Python 없음**, perl은 있음)
- 씬이 프리팹 값을 덮어쓰는지 확인: 씬 파일에서 `propertyPath: <칸 이름>` grep
- 컴파일 확인: 프로젝트 루트에서 `Assembly-CSharp.csproj`(에디터 코드면 `Assembly-CSharp-Editor.csproj`) → `TmpCheck.csproj` 복사 → 새 .cs가 없으면 `<Compile Include="Assets/…/새파일.cs" />` 줄 추가 (csproj 안은 `\` 경로라 perl로 기존 줄 뒤에 붙이기) → `dotnet build TmpCheck.csproj -nologo -v q` → `TmpCheck.csproj` 지우기. 경고 개수는 빌드마다 달라짐, 오류 0개만 보면 됨
- 셰이더는 밖에서 컴파일 확인이 안 됨 → Unity Console에서 확인해 달라고 하기
- 문서(.md·.tsv)는 CRLF. .cs는 그 파일의 기존 줄바꿈 그대로. 고친 뒤 `file 파일명`으로 확인
- 한글 폰트 `NotoSansKR-Regular SDF`는 고정 아틀라스 → **✕·✓ 같은 기호가 없음** (네모로 나옴)
- 유니티가 플레이 모드 중이면 스크립트를 새로 컴파일하지 않음 → 플레이 모드를 끄고 Ctrl+R
