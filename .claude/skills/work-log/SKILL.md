# 작업기록 추가

사용자는 이 기록을 나중에 **기술문서의 재료**로 씁니다 ("구조 → 설계 이유 → 트러블슈팅"). 그래서 "무엇을 만들었나"보다 **무엇과 무엇 사이에서 왜 이걸 골랐나**, **어디서 막혔나**가 핵심입니다. 나중에 혼자 다시 읽어도 이유가 이해돼야 합니다.

## 1. 기존 파일부터 읽기

- `Assets/01. Docs/작업기록.md`의 목차(`grep -n "^#"`)를 보고, 이번 내용과 가까운 섹션 한두 개를 실제로 읽어 형식·말투를 맞춥니다. 형식은 시간이 지나며 조금씩 바뀌니 **가장 최근 섹션**을 기준으로 삼으세요.
- 이미 같은 작업이 적혀 있으면 새로 쓰지 말고 그 섹션을 보충합니다.

## 2. 대화에서 재료 모으기

대화 전체를 훑어서 아래를 뽑습니다.

**고른 것 (선택지 표)**
- 사용자가 직접 고른 것, 그리고 추천안을 받아 "응"/"그렇게 해 줘"로 받아들인 것.
- 고른 이유는 **사용자가 말한 이유**를 우선합니다. 사용자가 이유를 말하지 않았으면 대화 맥락에서 드러난 기준(예: "클립에서 같이 들어가게 하고 싶어")을 적습니다.
- 추천했지만 사용자가 고르지 않은 것, 아직 안 정한 것은 ✅를 붙이지 않습니다. 대화 이후에 실제 코드가 어느 쪽으로 구현됐는지 확인할 수 있으면(`Grep`으로 해당 클래스·함수) 그걸 기준으로 ✅를 붙이고 "나중 구현은 A" 처럼 한 줄 적습니다. 추천과 실제가 다르면 그 사실을 남기는 게 기술문서에 더 쓸모 있습니다.
- 측정값·참고값(예: 클립에서 잰 구간)은 결정이 아니므로 "참고"로 따로 둡니다. 사용자는 값을 직접 정하는 걸 원합니다.

**헷갈린 개념 (어려웠던 개념 표)**
- 사용자가 "왜?", "이게 뭐야", "헷갈려", 잘못 이해한 질문을 한 곳.
- 사용자가 직접 묻지 않았어도 설명이 필요했던 개념은 넣되, 마지막 답변에서 "직접 헷갈린다고 한 건 아니라 설명이 필요했던 걸 넣었다"고 알려서 사용자가 빼거나 고칠 수 있게 합니다.

**그 밖에 (있으면)**: 전체 흐름, 바뀐 파일, 트러블슈팅(증상 → 원인 → 해결), 남은 것 체크리스트.

## 3. 형식

기존 파일과 같은 모양을 씁니다. 짧은 명사형 문장, 한국어, 코드·파일·필드 이름은 백틱, 고른 것은 **굵게 + ✅**.

```markdown
### N. 제목

#### 전체 흐름
| 순서 | 어디 | 무슨 일 |
|---|---|---|

#### 고민한 것과 트레이드오프

**1. 질문 형태의 제목**
| 선택지 | 장점 | 단점 |
|---|---|---|
| A) 안 | … | … |
| **B) 고른 안** ✅ | … | … |
- 기준: 왜 B인지 한두 줄 (사용자가 말한 이유 우선)

#### 어려웠던 개념
| 개념 | 헷갈린 점 | 정리 |
|---|---|---|
| 이름 | 사용자가 헷갈린 지점을 질문처럼 | 짧은 답. 핵심은 **굵게** |
```

- 선택지가 여러 개인 작은 결정이 많으면 기존 7-1처럼 `| 고른 것 | 선택지 | 장점 | 단점 |` 한 표로 묶어도 됩니다.
- 누가 했는지 표시하지 않습니다 (🤖, "Claude가", "누가" 열 금지). 사용자가 명시적으로 원하지 않았습니다.

## 4. 넣을 자리

- 파일은 날짜별 `## MM/DD` 섹션으로 나뉩니다. **작업한 날짜** 섹션에 넣습니다 (오늘 날짜가 아니라). 그 날짜 섹션이 없으면 날짜 순서에 맞는 자리에 새로 만들고, 나중에 정리한 거면 제목에 `(MM/DD에 정리)`를 붙입니다.
- 같은 날짜 안에서는 다음 번호(`### N.`)를 이어 씁니다.
- 날짜 섹션 사이에는 `---` 구분선이 있습니다.
- 마지막 커밋을 알 수 있으면 날짜 섹션 첫 줄에 `마지막 커밋: \`해시 메시지\``.

## 5. 쓰기

- 파일은 **CRLF** 줄바꿈입니다. 넣는 내용도 CRLF로 맞춥니다.
- 이 파일은 다른 세션도 동시에 고칩니다. 긴 내용을 준비한 뒤에는 **넣기 직전에 다시 읽고** 넣을 자리를 다시 찾으세요 (미리 잡아 둔 줄 번호는 틀릴 수 있음). 넣은 뒤 `grep -n "^## \|^### "`로 순서를 확인합니다.
- 커밋하지 않습니다. 사용자가 직접 합니다.

## 6. 끝나고 알려 줄 것

- 어느 날짜·몇 번째 줄에 넣었는지 (파일 링크).
- 표마다 무엇을 ✅로 표시했는지 한 줄씩. 특히 추천과 실제 구현이 달랐던 곳.
- 사용자가 직접 헷갈린다고 하지 않았는데 넣은 개념이 있으면 그 사실.
